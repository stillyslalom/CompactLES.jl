Write output and restart

Write a visualization frame

save_vtk(
    solver,
    Q,
    "output/flow";
    fields = (:rho, :velocity, :pressure, :schlieren),
    stride = 2,
)

Open the resulting .pvtr or .pvts container in ParaView or VisIt. Each MPI rank writes one piece. Resolved cylindrical and spherical angles produce a curvilinear grid with positions and velocity vectors rotated into Cartesian components.

Useful derived fields include :vorticity, :qcriterion, :divergence, :mach, :schlieren, :sensor, and the artificial-property fields. See DEFAULT_VTK_FIELDS and save_vtk for the full list.

Reduce output volume

stride selects points on a common global lattice:

save_vtk(solver, Q, "coarse"; stride = (4, 2, 1))

Write one global-index plane with slice:

save_vtk(solver, Q, "midplane"; slice = (3, 128), stride = 2)

Slicing usually saves more space than striding for a three-dimensional time series. Field construction still occurs on the local block before sampling, so these options reduce I/O volume and leave RHS cost unchanged.

Write a time series

FieldWriter numbers frames and maintains a .pvd collection with their physical times:

writer = FieldWriter(
    "output/frame";
    fields = (:rho, :pressure, :velocity),
    slice = (3, 128),
)

output = Callback(EveryTime(0.01), writer)
run!(solver, Q; tfinal = 1.0, callback = output)

Because EveryTime lands steps exactly, the collection has a uniform physical time axis.

Restart with the same decomposition

The dependency-free checkpoint path writes one file per rank:

save_checkpoint(solver, Q, "restart/state")
load_checkpoint!(solver, Q, "restart/state")

The restarting solver must have the same global grid and process grid.

Restart on another rank count

Load HDF5 before CompactLES uses the extension:

using HDF5
using CompactLES

save_checkpoint_hdf5(solver, Q, "restart/global")
load_checkpoint_hdf5!(solver, Q, "restart/global")

The shared checkpoint stores one global state and can be restored onto a different decomposition. hdf5_parallel reports whether the loaded HDF5 library can write collectively through the run's MPI implementation; otherwise rank zero gathers and writes.

For shared visualization output, save_hdf5 writes one .h5 frame and an XDMF sidecar. This avoids one file per rank per frame at large process counts.
